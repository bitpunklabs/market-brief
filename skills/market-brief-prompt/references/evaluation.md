# Evaluation and evolution

## Semantic acceptance

Review the prompt as an executable research assignment. Cite the passage carrying
each obligation and assess whether it guides execution concretely. Compare
responsibilities and usable meaning rather than headings or keyword matches.

| Dimension | Acceptance evidence |
| --- | --- |
| Request fidelity | Market/cadence/parameters exact; focus versus restriction clear; consistent language |
| Time | Default/explicit/historical windows, endpoints, vintages, updates and forward horizons resolved |
| Evidence | Broad scan, original sources, expectations, chronology, counterevidence and uncertainty |
| Data meaning | Market-specific sample/unit/flow/stock/return distinctions usable |
| Depth | Operating delivery, pricing, market mechanisms and cadence responsibilities represented |
| Outlook | Earlier questions drive judgment, mechanism, new evidence/horizon; real prior reports govern scoring |
| Delivery | Complete self-contained prompt; sourcing/format/length and missing-data treatment |
| Generative value | Task-specific synthesis; affirmative instructions; less repetition with retained depth |

For controls, read the matching file under `../assets/prompts/`. Compare omitted,
preserved and improved responsibilities with passage evidence. A missing material
obligation triggers revision even if the candidate is shorter. Retain drafts and
reviews in the requested test destination, separate from controls. Revise the
smallest responsible reference/instruction and regenerate affected cases; shared
changes warrant related-market/cadence checks. Stop local iteration when material
losses are resolved and further edits offer only stylistic churn. Record uncertainties.

Generation tests demonstrate prompt usability and semantic coverage. Research
quality is a separate comparison: execute candidate/control with matched market,
date, cutoff, source access and model settings; judge factual accuracy, evidence,
analysis, useful outlook, repetition and completeness. Stronger-report claims need
report artifacts rather than only self-review or text length.

## Capability-driven upgrades

On a requested upgrade, identify the target capability/constraint from supplied
information or current official docs: usable context, reliable search/tools,
numerical checking, synthesis, or context budget. Translate it into a testable
prompt change: deeper evidence integration, greater research discretion,
consolidated instructions, or a newly feasible analytical responsibility.

Preserve the old prompt and obligations. Compare daily and longer-horizon tasks,
historical cutoffs, missing/delayed data and true-prior-report review. Change
persistent references for improvements supported by observed tests; record target,
changes, evidence and limits in the requested artifact. Better host judgment can
improve generation with unchanged resources; upgrades are evaluated changes.

## Another market

Resolve exchange/jurisdiction and investable universe. Build a small profile from
official sources: calendar/time zone/sessions, currency, benchmarks/classification,
regulators/disclosures, macro/policy transmission, company/financing mechanisms,
publication lags and product rules. Verify institutions during adaptation; current
news/prices/judgments belong to the receiving research model.

Reuse shared capabilities and cadence requirements, with local distinctions in the
profile. If verification is unavailable, identify the missing institutional facts
before claiming a verified adaptation. A one-off profile can live with output/review;
a maintained market adds one profile and routing row. Apply the same acceptance
dimensions and compare local expert references when available. The eleven controls
cover their own markets/cadences.
