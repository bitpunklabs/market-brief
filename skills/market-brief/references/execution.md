# Execution requirements

The registry owns task-to-tier mapping. Obtain capabilities once per run from
actually exposed host metadata/tools: source, retrieval time, completeness,
candidate models, supported effort options, visible tools and permission limits.
A public catalog or static allowlist is not proof of authorization. No new
service, credential scan, paid probe or global settings change is needed.

Choose light/medium/heavy bindings by the task's reasoning, context and tool needs
and available comparative information. Record a short reason for each. Do not
rank versions or effort strings as a capability score. Heavy need not use max;
all tiers can share one configuration. With no reliable choice interface,
inherit the current session and label binding/control limits honestly.

Keep requested, host-accepted and observable actual settings distinct. Unknown
actual model/effort remains null with a reason. Record task ID, required tier,
applied tier, control (inherited/uncontrolled/host_applied), configuration results,
fallback and any actual usage. Escalating a question is valid; silently lowering
verify/analyze/review requirements is not. A routing limitation does not itself
make research partial.

After a rejected configuration, exclude it for this run and choose an available
alternative or inherit the current session. Do not loop on rejected settings.
Refresh only affected bindings when capability/tool state changes. New runs use
new capability observations rather than persistent model IDs.

The main agent reads decisive originals and retains research/review responsibility.
Delegate only when authorized and worthwhile; do not create one worker per tier
or chapter. Any delegated task receives the same cutoff, scope, relevant rules,
evidence and unresolved questions. Return data/review results for main-agent
integration; do not concurrently write the final report. Host-specific API
application and comparative multi-configuration runs remain separate runtime
acceptance work; this helper does not call or select models.
