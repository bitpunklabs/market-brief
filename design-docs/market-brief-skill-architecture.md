# Market Brief Prompt Skill：技术设计

2026-10-07。一个 skill、三层语义资源、手写对照组。功能约定见[功能设计](market-brief-skill-design.md)。

## 1. 文件与职责

```text
skills/market-brief-prompt/
  SKILL.md                      请求解析、设计/生成/自审与交付
  references/
    research.md                 跨市场功能模块
    cadences.md                 频率职责与时间边界
    markets/{cn,us,crypto}.md    市场机制及数据语义
    evaluation.md               对照审查、能力升级、市场扩展
  assets/prompts/               11份手写对照组
initial-prompts/                同一对照组的仓库副本
design-docs/                    功能与技术设计
temp/                          忽略的生成样例、迭代与比较证据
```

全部运行依赖位于 skill 内，复制目录即可使用。宿主模型负责生成；文件存研究设计。此版无需模型客户端、数据库、运行时模板引擎或外部服务。

## 2. 运行流程

```mermaid
flowchart LR
  A[请求或旧 prompt] --> B[读取共享能力 频率 市场]
  B --> C[设计目标 证据职责 信息边界 结构]
  C --> D[生成完整新 prompt]
  D --> E[语义自审并修订]
  E --> F[交付完整 prompt]
  F --> G[接收模型完成研究报告]
  D -. 已有对应对照 .-> H[读取手写对照]
  H --> E
```

模块不是文本插槽，正文由模型综合生成；结构可变，重要职责可审计。生成阶段读取共用能力、频率文件的相关部分、一个市场画像和验收说明。已有对应对照时，完整对照在初稿之后用于交付前语义审查，减少照抄原结构的锚定。生成输出自包含，接收端无需访问本 skill。

参数优先级：用户明确要求 → 市场/频率特征 → 共用默认。覆盖重点与范围限制分开；prompt 和报告默认 CN=zh、其他市场=en，明确语言请求覆盖默认，语言要求一致覆盖全文；篇幅单位随语言适配。模型配置在执行环境，生成正文是研究任务。

## 3. 最小维护方式

共享原则只在 research.md 定义；频率差异只在 cadences.md 定义；局部制度/经济权益/数据含义只在对应 market profile 定义。入口保留路由与生成方法。验收文件保留语义检查和演进操作。职责交叉时由生成模型整合为一次完整说明。

对照组独立于生成规则；修改模块无需同步重写所有手写 prompt。基线有意更新时同步 assets 与 initial-prompts 并记录原因，比较采用冻结版本/hash。历史原文保留在 Git。

新市场增加一个画像和一行路由，复用频率与研究能力。制度核验使用官方来源；当官方核验受限时，产物说明尚未确认的制度边界。

## 4. 设计迭代记录

本次设计经过三轮审查，详细记录保存在 temp/generative-prompt-v1/iterations/design-review.md。

1. 初始提案把功能拆成大量文字片段。审查发现这容易变成拼接器，并增加维护成本；最终用三层语义资源和模型综合设计。
2. 按11份对照逐项核对。审查补入市场数据含义、频率端点、预测期限、样本和披露滞后，以保持研究深度。
3. 检查演进与扩展。明确能力升级需要比较证据、普通生成与基线比较分开、新市场先验证机构画像、prompt测试与实际报告质量分别验收。

生成产物另按实际比较结果迭代；保留11个组合、2个参数案例、3个独立上下文前向案例，并以新上下文月度案例回归修订后的模块。记录初稿、发现、模块改动与修订产物。少量明确改动优于累积通用提醒。

## 5. 验证

本地验证 frontmatter、内部链接、可独立安装、对照副本一致性、生成文件完整性与参数边界。文本扫描帮助定位问题；人工语义比较判断职责是否保留和表达是否可执行。

本次生成覆盖11个基础组合，补充历史截止、语言/重点和范围适配。记录生成者为当前宿主 agent，未配置或假称另一个运行模型。所有样例是真实生成的任务文本，脚本仅保存、统计、校验和记录 hash。

实际研究质量 A/B 比较另需冻结市场/日期/截止、来源访问与模型设置并保存双方报告。此版生成测试不执行实时市场报告。校验方法不引入运行框架或长期评分服务。

## 6. 提示设计依据

参考[OpenAI reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)：清楚定义目标与关键约束，给模型研究方法的裁量空间，按结果验证简化效果。本设计采用能力职责与语义验收，初稿从职责生成，完整旧模板用于事后比较。官方页面已在本轮实际读取，摘录及访问方式保存在测试目录。
