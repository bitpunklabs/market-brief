# Market Brief Prompt Skill：功能设计

日期：2026-10-07。当前方向：恢复原始prompt engineering，以完整研究prompt为交付物。技术实现见[技术设计](./market-brief-skill-architecture.md)。

## 1. 目标与边界

`market-brief-prompt` 根据市场、频率和用户参数，生成可直接复制或保存的完整市场研究prompt。用户把它交给执行端可用的最高能力研究模型，并设置该模型支持的最高reasoning effort，让同一个模型从检索、核验到分析、展望、写作和自审完成整份报告。

核心闭环是：识别请求 → 选择原始模板 → 适配明确参数 → 检查一致性 → 交付完整prompt。生成阶段不代替执行模型搜集新闻、筛选行业或形成市场判断，也不把完整研究拆成不同模型或不同上下文的任务。

## 2. 输入与默认行为

| 输入 | 行为 |
| --- | --- |
| 市场与频率 | 必需，可从明确上下文识别；缺失或冲突才澄清 |
| 日期或区间 | 可选；给定值准确写入prompt，未给则保留原模板运行时选择规则 |
| 信息截止 | 可选；显式截止约束研究，历史请求不得纳入后续信息 |
| 重点 | 加深相关研究，不默认收窄其他扫描 |
| 限定范围 | 明确改变覆盖对象，要求报告说明范围 |
| 报告语言 | 全部原始模板默认中文；明确要求其他语言时一致修改语言与长度规则 |
| 旧报告 | 仅引用用户提供或明确可访问的真实材料，不虚构历史判断 |
| 保存位置 | 可选；生成UTF-8 Markdown，未指定时直接交付完整prompt |

生成prompt时不预先假设交易日或固定“今天”。执行模型运行时核验实际时间、交易所日历、时区、夏令时和早收盘安排，再按所选模板确定研究窗口。显式指定日期、截止和区间若相互冲突，应先澄清。

原始美股与Crypto模板虽用英文撰写指令，仍要求中文报告；不再默认改为英文。报告语言和指令语言是两回事。

## 3. 支持范围

恢复原有11个组合：A股、美股各支持盘前、盘后、周度、月度；Crypto支持日报、周度、月度。暂不以通用模板冒充其他市场或不支持频率。

| 频率 | 完整prompt的研究职责 |
| --- | --- |
| 股票盘前 | 新信息与定价变化、跨市场传导、开盘后验证和事件风险 |
| 股票盘后 | 当日行情与事件时序、真实盘前条件复核、盘后更新和下一交易日展望 |
| Crypto日报 | 连续24小时观察、现货/杠杆/供给、未来24–72小时条件与近期催化 |
| 周度 | 完整周、多周趋势和轮动、驱动持续性、下周与中期验证 |
| 月度 | 自然月、经营或协议经济、盈利/估值/供给约束、未来1–3个月验证 |

具体章节、背景窗口、篇幅与数据标准采用对应原始模板。周/月prompt不由日频prompt或短期报告拼接而来。

## 4. Prompt engineering 原则

原始11份prompt是研究设计的主体，不压缩成公共研究流程或简短摘要。适配只处理用户明确给出的参数，不删掉市场和频率专属义务。

生成的prompt应完整保留：

1. 先广泛扫描再选择重点，寻找反向材料，重大事实优先核验原始发布资料。
2. 区分事实、推断与待验证假设；预期必须有来源，不能把相关性直接写成因果。
3. 分开数据所属期、首次公开时间、更新和行情端点；历史研究不能偷看后续修订或结果。
4. 沿事实、预期变化、传导机制、市场反应和下一验证条件展开，不做新闻堆砌。
5. 保留宏观、重大事件、跨市场、行业/主题与代表实体的实质分析，不用概念标签代替经营联系。
6. 保留条件性后市展望、期限、确认与失效条件；未校准时不编精确概率或技术点位。
7. 按实际原报告复核旧判断；没有原报告时不虚构连续研究记录。
8. 保留来源、数据缺失、统计口径与Markdown排版要求，数量不足不凑数。

A股政策须经过资格、执行、订单/成交、回款/利润的验证；美股保留财报与指引口径、权重/等权及盈利期限比较；Crypto保留供给、现货与衍生品、采用与价值捕获、协议及系统风险。

生成阶段不填入最新报价、新闻结论或未经核验的事件日期。执行阶段的实时研究由同一个接收模型完成。

## 5. 单模型执行约定

完整prompt交给一个最高能力模型，并由执行端设置该模型当前支持的最高effort。检索、核验、分析和写作是该模型完成报告的研究步骤，不是独立模型角色或调度节点。

模型与effort由执行端设置。生成结果只包含完整研究prompt，不附加模型选择、effort或执行配置交接说明。

本项目不实现能力探测、模型排名、自动调度、委派、任务档位、token计费或报告运行日志。用户要求的是生成prompt；生成成功不表示研究已经执行。

## 6. 交付与验收

交付完整可执行prompt，不能只给模板路径、框架或“请参考附件”。请求参数应明确且没有冲突；未指定项保留模板可执行的默认行为，不留下必填占位符。

验收分开检查：模板保真、适配一致性、可复制使用与执行端报告质量。前者通过不证明后者通过。后续研究质量比较可以把完整prompt直接交给目标模型执行，但不为该比较重建任务分级框架。

使用示例：

```text
$market-brief-prompt 生成A股盘前prompt。
$market-brief-prompt 生成美股盘后prompt，重点分析财报和利率。
$market-brief-prompt 生成Crypto月度复盘prompt，目标为2026年9月，仅使用月末前信息。
```

## 7. 原始任务的特征保留清单

章节与表头遵循原模板，显式语言要求优先。下表以原始prompt的实质内容作为保真清单。

| 任务 | 必须保留的特征 |
| --- | --- |
| A股盘前 | 核心结论；5–8 项重要新闻但不足不凑；宏观跨市场；约 6–8 个方向；三种情景；开盘/午间/收盘前观察；当日及未来 5 交易日风险；最后三件事 |
| A股盘后 | 指数与多数股票分开；新闻反应时序；行业主题分开；跨市场反证；真实盘前判断复核；盘后新信息；下一交易日情景；判断修正 |
| A股周度 | 4/13 周背景；周内拐点；日均成交和全周个股收益统计；催化预期；政策跨市场；行业持续性；周末更新；下周及 2–4 周事件；下期交接 |
| A股月度 | 3/6 月背景；宏观信用政策链；盈利与估值分别研究；行业周期；资金与股票供给；下月及 1–3 月验证；月度判断更新 |
| 美股盘前 | 双时区与交易状态；财报指引独立章节；权重/等权和大/小盘；宏观事件预期；开盘 30–60 分钟和发布后验证；期权持仓推断限制 |
| 美股盘后 | 隔夜缺口与盘中收益按复利连接；真实权重数据才做指数贡献；事件反应顺序；盘前复核；盘后业绩与电话会初步状态；下一交易日条件 |
| 美股周度 | 4/13 周背景；GICS 广泛扫描；盈利与同行/产业链验证；周末更新；持仓披露滞后；下周及 2–4 周事件；方向/机制/时机分开评价 |
| 美股月度 | 宏观与利率预期；盈利周期和样本质量；估值、预测期限与风险定价；中期行业；全球资金与集中度；期后更新；下月情景与判断复核 |
| Crypto 日报 | 快照非收盘；7/30 日背景；约 3–5 项事件与约 3–5 个重点方向；现货/杠杆/供给；陈旧跨市场报价；实际前报才复核；24–72 小时情景与 7 日催化 |
| Crypto 周报 | 完整 UTC 周及 4/13 周背景；约 4–6 项事件、约 5–8 个方向；流量与衍生品供给分开；协议价值捕获；期后更新；约 3 条可复核周度假设 |
| Crypto 月报 | UTC 自然月及 3/6 月背景；日均活动和存量/流量区分；采用/持有人经济；供给与估值约束；约 6–10 个重点方向；基础设施风险；约 3 条中期假设 |

数量目标只控制聚焦程度。执行模型不必恰好找满候选数量；完整prompt保留不足不凑数与按证据调整篇幅的规则。
