# Market Brief Prompt Skill：功能设计

2026-10-07。目标是可演进的生成式研究 prompt skill：从研究能力、市场机制和频率职责设计完整任务，由同一个接收模型完成研究与报告。

## 1. 交付与输入

交付物是完整、自包含的研究 prompt。生成阶段负责研究任务设计，执行阶段负责联网取证、计算、归因、判断、展望和写作。模型与 effort 由执行环境设置。

市场和频率是必要输入，可从明确上下文识别；日期/区间、信息截止、重点、限定范围、语言、已有报告和保存位置可选。prompt 和报告默认语言一致：CN 为中文（zh），其他市场为英文（en）；用户明确指定时覆盖默认。英文篇幅按词数设编辑目标，中文按字数，保持相近分析深度。重点增加深度，限定范围改变覆盖。未给日期时保留执行时选择规则；历史请求保留当时可知信息边界。参数冲突先解决。

## 2. 三层能力设计

模块是语义职责，不是可直接拼接的文字片段。共用文件内部划分功能模块，避免一个小原则一个文件。

| 层 | 内容 | 维护位置 |
| --- | --- | --- |
| 跨市场研究能力 | 证据与预期差；时间与计量；定价传导；经营与行业主题；展望/风险/连续复核；交付质量 | references/research.md |
| 市场机制 | 制度/原始来源、宏观传导、经济权益、数据含义、供给和风险 | references/markets/{cn,us,crypto}.md |
| 频率职责 | 盘前、盘后、连续日报、周度、月度的窗口、深度、验证期限和交付重点 | references/cadences.md |

证据方法共用，但政策执行链属于 CN、财报/指引与预测期限属于 US、协议活动到持有人权益及供给口径属于 Crypto。频率控制研究职责，市场决定具体边界。例如同为周报，股票的周末信息是期后更新，而 Crypto 的周末行情属于完整 UTC 周。

## 3. 生成方式

理解任务 → 读取共用能力/选定频率/对应市场 → 设计任务目标与报告结构 → 写完整新 prompt → 语义自审及已有对照审查 → 修订并交付。

生成 agent 可重组章节、合并重复要求、根据重点安排分析深度，保留必要义务。输出说明接收 agent 应确定什么、需要什么证据、怎样处理数据与不确定性。使用正向任务表达，把禁止式提醒转成正确分析、数据边界或计算要求。

展望围绕前文实质未决问题：当前更有依据的判断、经营兑现与定价预期的差距、传导机制、相关前提和反证、下一项值得取得的证据及期限。对象可以是市场、行业、主题或实体。原判断延续时更新证据与未解环节。

时间、日历、当前产品规则与行情在执行时核验。生成阶段给出任务约束和信息边界，行业主题的实时筛选由执行模型根据研究完成。用户提供的材料可以作为明确上下文。

## 4. 原 prompt 的作用

`skills/market-brief-prompt/assets/prompts/` 的 11 份手写完整 prompt 是对照组。生成先用能力模块独立起草，交付前读取匹配对照，检查研究职责的保留、遗漏、强化和重复。前向测试显示初稿仍可能遗漏细节，因此已有对照的组合默认保留这道语义审查。对照组既提供质量基线，也暴露旧表达可改进之处。

`initial-prompts/` 保留相同对照的仓库副本，原始版本在 Git 历史中。能力模块成为生成规则的维护主体；二者允许不同表达与结构。模块迭代时保留基线以识别真实得失，基线的有意变更要单独记录。

## 5. 质量底线

| 任务 | 重要专属义务 |
| --- | --- |
| CN 盘前 | 长假/闭市完整窗口、5/20交易日背景、政策兑现链、跨市场业务映射、当日及5交易日事件 |
| CN 盘后 | 指数与多数股票、新闻反应时序、统计范围/披露滞后、真实盘前核对、盘后独立更新 |
| CN 周度 | 实际交易周、4/13周、日均活跃度、全周个股收益宽度、政策/盈利持续性、2–4周验证 |
| CN 月度 | 自然月/3–6月、信用与财政传导、盈利/估值分开、经营周期、股票供给、1–3月验证 |
| US 盘前 | 双时区/DST、行情状态、财报指引独立研究、权重/等权和大小盘、5交易日事件 |
| US 盘后 | 隔夜/盘中收益复利连接、真实权重贡献、反应时序、盘前复核、盘后电话会初步状态 |
| US 周度 | 4/13周、GICS扫描、财报同行/供应链、样本覆盖/权重、周末与持仓滞后、2–4周验证 |
| US 月度 | 宏观与政策路径、盈利修订/NTM滚动区分、估值期限/样本、全球资金/集中度、1–3月验证 |
| Crypto 日报 | T快照/24小时、历史日默认UTC截止、7/30日、现货/杠杆/供给、跨资产陈旧报价、24–72小时与7日催化 |
| Crypto 周报 | Monday-to-Monday完整UTC周/4–13周、周末属于复盘、流量/杠杆/供给、协议权益、期后更新 |
| Crypto 月报 | UTC自然月/3–6月、流量日均和存量、采用/持有人经济、供给/估值、基础设施风险、1–3月验证 |

各组合共同保留来源、预期差、反证、事实/推断/假设、历史版本边界、缺失数据、真实前报复核、自然展望和稳定 Markdown。约略篇幅与数量服务聚焦；信息完整性优先。

## 6. 随模型能力演进

生成使用宿主模型的当前能力，不固定型号或档位。更强的宿主可在相同职责上形成更好的任务设计；持续改进通过可观察比较确认。

升级请求明确目标能力或约束，例如更长可用上下文、更可靠工具、更强跨证据综合或更紧预算。保留旧 prompt 与职责，提出具体改动，生成代表样例，比较后决定是否改能力模块。简化脚手架、增加有用的综合分析，都要保持证据与市场义务。能力说明来自用户或当前官方材料；效果来自测试。

## 7. 扩展市场

新增市场先明确交易所/辖区/覆盖对象，用官方材料建立时区日历、币种、基准、行业分类、披露、宏观传导、资金/供给与规则画像。复用共享能力和适用频率。维护版本只增加一个市场画像与入口索引行；一次性适配可把画像保存在测试目录。明确区分机构事实验证和实时行情研究。

## 8. 验收

先检查完整 prompt 的语义覆盖和可执行性，再评价实际报告质量。比较产物用证据说明改进/保留/遗漏；修复重大遗漏后回归相关组合。真实质量提升需要相同市场/截止/来源访问/执行模型的候选与基线报告。当前生成测试仅证明 prompt 设计质量与覆盖，不能自动证明报告更优。

测试产物及迭代记录保存在忽略的 `temp/`。技术实现与验收操作见[技术设计](market-brief-skill-architecture.md)。
