# Market Brief Skill：功能设计

日期：2026-10-07。状态：设计基线；第一批 skill 规则与本地 helper 已实现，尚未安装或验证真实研究运行。实际实现与待验收范围见 [项目说明](../README.md)。技术约定见 [技术架构](./market-brief-skill-architecture.md)。

## 1. 目标与最小闭环

`market-brief` 接受一个市场和一种频率，直接交付有来源、可验证、有后市展望的市场报告。CN 默认中文，其他市场默认英文；显式语言要求优先。用户不必配置模型、提供股票池或复制另一段 prompt。

核心闭环为：确定研究边界 → 广泛发现证据 → 核验重点 → 分析与展望 → 审查交付。保留原 prompt 的宏观、重大事件、行业/主题、跨市场验证和条件性展望；具体研究范围随市场与频率变化。

模型分工使用 `light / medium / heavy` 三档任务需求。宿主 agent 根据本次实际可用的模型、effort、工具和权限决定映射，报告质量标准不随执行成本降低。三档不是三种报告套餐，也不保证启动三个 agent。

## 2. 用户输入与默认行为

| 输入 | 约定 |
| --- | --- |
| 市场、频率 | 必需，可从明确上下文识别；缺失或范围冲突时才澄清 |
| 日期/区间 | 可选；股票盘前选下一未开盘交易时段，盘后选最近完成时段，周/月选最近完整市场周/自然月；连续市场日报默认滚动 24 小时 |
| 信息截止 `as_of` | 当前研究取真实时点并冻结；历史请求采用目标期边界，不能默认加入今天的资料 |
| 报告语言 | CN 默认 zh-CN，其他市场默认 en；聊天语言不改变默认 |
| 重点、关注标的 | 可选；补充重点，不替代广泛扫描与反证 |
| 旧报告 | 可选；提供文件或明确的可访问报告目录，按原条件复核，不虚构历史判断 |
| 保存位置 | 可选；直接在聊天交付，文件宿主可保存正文和最小运行记录 |

wtd/mtd 或提前版必须明确标注未完成的研究期。期后更新需要单独的信息截止，与期内价格归因分开。用户显式限定股票池或交易所时，报告按该范围研究并标明范围，不能称全市场。

明确指定的目标日期优先于默认日期。“今天盘前”在开盘后执行时仍研究今天开盘前可知信息，并标历史重建；不能自动改成明天，也不能纳入今天盘中结果。用户给出的日期与 as_of 实质冲突时先澄清。

本 skill 默认自动分配任务档位、动态选择执行配置；用户通常只表达研究目标。宿主没有模型列表或不能切换配置时，沿用当前会话并记录执行限制；没有可靠当期证据时不冒充实时报告。执行限制与研究资料缺失是不同问题。

## 3. 初始任务与频率职责

首批支持原有 11 个组合，稳定 ID 为 `<market_id>.<cadence>`。股票支持 premarket/postmarket/weekly/monthly；Crypto 支持 daily/weekly/monthly。非法组合不静默替换。

| 频率 | 主要职责 |
| --- | --- |
| 盘前 | 新信息可能改变什么定价；开盘后怎样确认；当日事件风险 |
| 盘后 | 实际交易了什么；价格与新闻时序；原盘前条件复核；盘后更新 |
| 连续市场日报 | 24 小时供需、现货与杠杆变化；未来 24–72 小时验证 |
| 周度 | 多周驱动的持续性、扩散和轮动；下一周与 2–4 周检查点 |
| 月度 | 经营/协议经济、需求、估值与约束；未来 1–3 个月验证 |

周/月报直接审查相应区间的数据，不拼接短期报告。价格表现、经营或协议经济、催化兑现分别判断；一条新闻或一天波动不自动重置中期主线。

首批时区为 CN 的 Asia/Shanghai、US 的 America/New_York、Crypto 的 UTC；US/Crypto 重要事件同时给北京时间。新市场按当地报告与交易日历时区定义窗口，报告语言不改变区间或来源语言。

正文长度是可读性目标，不是填满配额。英文预算待实测校准；原始 prompt 保留为中文基线，语言默认变更单独评估。

## 4. 核心研究标准

1. 先扫基准、参与范围、主要行业/功能类别、宏观、重大实体事件与风险，再选择重点；已检查无变化、未检查和获取失败分开记录。
2. 搜索发现线索，核心事实读原始发布材料。反向材料和替代解释也进入筛选；转载不构成多项独立证据。
3. 判断沿“新事实 → 预期变化 → 传导机制 → 已发生反应 → 下一验证条件”展开。没有事前预期就不称超预期，相关性不能直接写成因果。
4. 区分事实、推断与假设；行情区间、公开时间、数据所属期、网页版本分开。收盘后消息不能解释此前走势，历史版不能偷看后续修订。
5. 后市展望给出基准、改善与恶化路径及触发、确认、失效条件和期限；没有校准不编精确概率。
6. 真有旧报告才按原文、原期限和条件评价方向、机制、时机与风险。未触发、仍待验证分别标注，不能事后改写假设。

市场专属分析必须保留：CN 的政策执行到订单与利润；US 的财报/指引、盈利口径及权重/等权；Crypto 的供给、采用、价值捕获与系统风险。来源记录不充分时缩小结论，不能用通用叙事填补。

## 5. 每项任务的默认档位

以下是唯一的任务分档约定；技术实现据此建立轻量映射，不按市场复制任务流程。

| 任务 ID | 任务 | 默认执行 | 升级/接受条件 |
| --- | --- | --- | --- |
| `resolve` | 识别市场、频率、语言、范围；读取运行能力并选择档位配置 | medium | 重大范围冲突先澄清；日期算术由代码完成 |
| `coverage` | 确定基准、主要类别、宏观/事件/风险扫描范围 | medium | heavy 在筛重点前复核重大遗漏 |
| `discover` | 搜索、来源定位、候选事件与反向线索 | light | 返回出处、时间及缺口，不独立裁定核心驱动 |
| `extract` | 普通事实、公开时间、单位与数据口径整理 | medium | 核心数字、时间冲突和历史版本问题升级 verify |
| `verify` | 重大事实、核心数字、历史可用性与因果时序核验 | heavy | 重读关键原文及反证，不只读低档模型摘要 |
| `analyze` | 驱动排序、宏观与市场结构、行业/主题及替代解释 | heavy | 明确价格、经营与催化之间的证据边界 |
| `review_previous` | 对实际旧报告的条件与判断复核 | heavy | 没有原报告时省略；保留原判断不改写 |
| `outlook` | 条件性路径、检查点、期限与失效条件 | heavy | 不把已发生结果写成尚待验证预测 |
| `write` | 整合正文、关键数字、来源和后市展望 | heavy | 结论前置、各章节一致 |
| `format` | 标题、短表格、引用导出与可读性整理 | light | 不改写数值、证据或观点；改义进入 review |
| `review` | 最终事实支持、时序、归因与整体一致性审查 | heavy | 不支持的核心结论补证、降低或删除 |
| — | 日历/时区计算、收益复算、记录保存与结构校验 | 确定性代码 | 仅使用实际输入；不需要模型档位 |

档位是工作需要，不是一个必须单独调用的节点；主 agent 可以合并相邻工作。关键问题按问题升级到 heavy，不把整份报告无条件重跑。heavy 也不等于最高 effort，应选择适合工作且当前支持的配置。

## 6. 全球市场扩展

市场按研究范围而非聊天中的国家名称定义。一个市场资料包明确资产类型、覆盖交易所/基准、时区与交易时段语义、日历来源、币种、类别划分、主要披露来源、市场机制与支持频率。

首批只有 CN、US、Crypto。HK、日本、英国、加拿大、澳大利亚、印度等是后续候选；增加一个市场需补资料包和真实案例后登记支持，不能仅新增名字就宣称已具备研究能力。新市场默认英文，来源可以使用当地语言。

“欧洲市场”可能覆盖多个交易所和时区，需要先确定区域基准及覆盖范围。复合范围以选定基准定义报告窗口，对各交易所/行情保留实际时点；不用一个假日历覆盖整个区域。多市场请求先输出各自独立简报，再按需要比较，避免把不同时点和币种直接混算。

股票通用方法共用，地方差异放市场包。新资产类型确有不同研究义务时才增加资产类型参考；当前不预建债券、商品、外汇引擎。原始 11 个 task ID 与既有方法保持兼容。

## 7. 交付、缺失与连续研究

正文给出时点与范围、核心结论、市场与宏观/事件分析、重点行业/主题、后市展望、事件日历及失效条件；旧判断复核只在材料实际存在时出现。来源就近，内部模型路由和日志进入运行记录。

可靠证据有缺项时交付限定范围的 partial；连研究目标或关键行情日期都无法确定时，说明原目标未完成。没有网络且无可靠当期输入时仅能分析已给材料，并标非实时。代码校验通过不代表经济解释正确。

连续研究通过可访问的实际旧报告与检查点交接完成。没有旧报告仍能研究，当前版本不维护独立主题数据库或状态机；原假设与发表时间保留，不把历史重跑当真实过去预测。

## 8. 用户如何使用

下面是未来实现并被宿主发现后的使用方式，当前尚未安装。Codex CLI 可用 `$market-brief` 显式调用，见 [Codex skill](https://learn.chatgpt.com/docs/build-skills)；Claude Code 可用 `/market-brief`，见 [Claude Code skill](https://code.claude.com/docs/en/skills)。自然语言请求也可触发，取决于宿主对 skill 的识别。

```text
$market-brief 生成今天的 A 股盘前简报。
$market-brief 生成最近完整交易日的美股盘后简报，重点关注财报和利率。
$market-brief 生成最近完整周的 Crypto 周报，用中文。
/market-brief 生成 2026 年 9 月的美股月报，只使用该月末之前公开的信息。
```

模型选择在后台完成，用户不用填写三个 model ID 或 effort。报告注明实际目标日、区间与截止；默认 CN 中文，其余英文。指定重点只是加深研究，显式限定股票池才改变范围。提供真实上一期报告即可要求复核其中判断。

增加 HK 市场包并验收后，可用同样方式请求“港股周报”；尚未支持时说明需要补市场包。报告保存是文件输出能力；定时运行、提醒和分发由宿主另行提供，不因调用 skill 自动开启。

## 9. 原始任务的特征保留清单

章节名称和表头按 resolved report language 输出，公共组件不强求章数一致。下表以原报告的实质内容作为验收清单。

| 任务 | 必须保留的特征 |
| --- | --- |
| A股盘前 | 核心结论；5–8 项重要新闻但不足不凑；宏观跨市场；约 6–8 个方向；三种情景；开盘/午间/收盘前观察；当日及未来 5 交易日风险；最后三件事 |
| A股盘后 | 指数与多数股票分开；新闻反应时序；行业主题分开；跨市场反证；真实盘前判断复核；盘后新信息；下一交易日情景；判断修正 |
| A股周度 | 4/13 周背景；周内拐点；日均成交和全周个股收益统计；催化预期；政策跨市场；行业持续性；周末更新；下周及 2–4 周事件；下期交接 |
| A股月度 | 3/6 月背景；宏观信用政策链；盈利与估值分别研究；行业周期；资金与股票供给；下月及 1–3 月验证；月度判断更新 |
| 美股盘前 | 双时区与交易状态；财报指引独立章节；权重/等权和大/小盘；宏观事件预期；开盘 30–60 分钟和发布后验证；期权持仓推断限制 |
| 美股盘后 | 隔夜缺口与盘中收益按复利连接；真实权重数据才做指数贡献；事件反应顺序；盘前复核；盘后业绩与电话会初步状态；下一交易日条件 |
| 美股周度 | 4/13 周背景；GICS 广泛扫描；盈利与同行/产业链验证；周末更新；持仓披露滞后；下周及 2–4 周事件；方向/机制/时机分开评价 |
| 美股月度 | 宏观与利率预期；盈利周期和样本质量；估值、预测期限与风险定价；中期行业；全球资金与集中度；期后更新；下月情景与判断复核 |
| Crypto 日报 | 快照非收盘；7/30 日背景；约 3–5 项事件与约 3–5 个重点方向；现货/杠杆/供给；陈旧跨市场报价；实际前报才复核；24–72 小时情景与 7 日催化 |
| Crypto 周报 | 完整 UTC 周及 4/13 周背景；约 4–6 项事件、约 5–8 个方向；流量与衍生品供给分开；协议价值捕获；期后更新；约 3 条可复核周度假设 |
| Crypto 月报 | UTC 自然月及 3/6 月背景；日均活动和存量/流量区分；采用/持有人经济；供给与估值约束；约 6–10 个重点方向；基础设施风险；约 3 条中期假设 |

数量目标只控制聚焦程度。执行规范不要求模型恰好找满候选数量；报告规格应允许有证据的较少记录和有理由的可选章节缩短。
